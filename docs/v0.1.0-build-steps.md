# pouch nRF54L15 Build Runbook

This document records the Windows build steps used while bringing up `pouch` on `xiao_nrf54l15`.

Two states were tested:
- `pouch` release `v0.1.0` (`73662de`) with NCS `v3.0.1`
- latest upstream `pouch` (`origin/main`, tested at `d161705`) with NCS `v3.2.3`

The XIAO nRF54L15 board is available in the newer NCS `v3.2.3` stack, not in the older `v3.0.1` stack used by `pouch` `v0.1.0`.

**For the current known-good build on this PC** (paths, exact `west build` command, flash), see **[section 11](#11-known-good-xiao-build-on-this-machine-may-2026)**.

## 1) Set `pouch` to the release commit

From `C:/ncs_pouch_soil/pouch`:

```powershell
git checkout 73662de
git show -s --oneline --decorate HEAD
```

Expected result includes:

```text
73662de (HEAD, tag: v0.1.0) ...
```

## 2) Build attempt and initial failure

From `C:/ncs_pouch_soil/pouch/examples/ble_gatt`:

```powershell
west build -b nrf52840dk/nrf52840 --pristine
```

This initially failed due to NCS revision mismatch and tooling issues.

## 3) Align NCS workspace revisions

From workspace root `C:/ncs_pouch_soil`:

```powershell
west update
```

Why: `nrf` was at `v3.0.1` while some imported projects (such as `zephyr`/`mcuboot`) were still at newer revisions. Aligning all projects removed Kconfig/toolchain incompatibilities from mixed versions.

## 4) Install required Python dependencies

From `C:/ncs_pouch_soil/pouch`:

```powershell
python -m pip install -r requirements.txt
python -m pip install cryptography
```

Why:
- `zcbor` (from `requirements.txt`) is required for code generation during build.
- `cryptography` is required by MCUboot `imgtool.py` for image signing.

## 5) Force the NCS-managed Zephyr SDK

Set environment variable before building:

```powershell
$env:ZEPHYR_SDK_INSTALL_DIR = "C:/ncs/toolchains/66cdf9b75e/opt/zephyr-sdk"
```

Why: build failures were seen when using a different host-installed SDK (`C:/Users/Brian/zephyr-sdk-0.17.2`). For this workspace, using the NCS-managed SDK resolved ABI/header/toolchain mismatches.

## 6) Successful build

From `C:/ncs_pouch_soil/pouch/examples/ble_gatt`:

```powershell
west build -b nrf52840dk/nrf52840 --pristine
```

Build completed successfully and generated:

- `build/ble_gatt/zephyr/zephyr.elf`
- `build/dfu_application.zip`
- `build/merged.hex`

## 10) XIAO sysbuild/MCUboot failure

The default sysbuild command recognizes the board, but fails while building MCUboot:

```powershell
west build -b xiao_nrf54l15/nrf54l15/cpuapp --pristine
```

Failure:

```text
C:/ncs_pouch_soil/bootloader/mcuboot/boot/zephyr/flash_map_extended.c:70:2:
error: #error "FLASH_DEVICE_ID could not be determined"
```

This means MCUboot could not determine the flash device that contains the boot slots for this board configuration. The application itself builds, so the issue is specifically the sysbuild/MCUboot flash and partition metadata for `xiao_nrf54l15`.

Until that flash metadata is fixed, use `--no-sysbuild` for direct app flashing and development. MCUboot is still needed later if the goal is bootloader-managed updates such as signed DFU/OTA images.

## Current soil sensor node stability notes

The current working XIAO soil sensor image is built app-only with:

```text
CONFIG_POUCH_THREAD_STACK_SIZE=8192
CONFIG_POUCH_UPLINK_PROCESSING_STACK_SIZE=8192
CONFIG_GOLIOTH_SETTINGS=n
CONFIG_GOLIOTH_OTA=n
```

Observed failure sequence before this change:

```text
<inf> cert: Server cert verified against CN pouch.golioth.io
<inf> main: Writing soil sensor uplink: path .s/sensor, content_type 50, len 44
<err> os: ***** USAGE FAULT *****
<err> os: Current thread: ... (pouch_work)
```

Increasing both Pouch stacks to `8192` made the soil-only image stable and the
gateway delivered repeated uplink blocks. Re-enabling `CONFIG_GOLIOTH_SETTINGS=y`
reintroduced the `pouch_work` crash even with OTA disabled, so the stable field
build keeps Golioth Settings off. This means Golioth Settings cannot currently
be used as a cloud-to-node command channel.

`CONFIG_GOLIOTH_OTA=n` is also used for the stable soil sensor image. The
application CMake now compiles `src/fw_update.c` only when
`CONFIG_GOLIOTH_OTA=y`, which keeps non-OTA builds valid while preserving the
ability to re-enable OTA for future investigation.

If flashing reformats LittleFS, re-upload the node credentials over the node's
COM port:

```powershell
$env:PYTHONUTF8='1'
smpmgr.exe --port COM8 --line-length 128 --line-buffers 2 file upload .\certs\<node>\device.crt.der /lfs1/credentials/crt.der
smpmgr.exe --port COM8 --line-length 128 --line-buffers 2 file upload .\certs\<node>\device.key.der /lfs1/credentials/key.der
```

Verify with:

```powershell
smpmgr.exe --port COM8 --line-length 128 --line-buffers 2 file read-size /lfs1/credentials/crt.der
smpmgr.exe --port COM8 --line-length 128 --line-buffers 2 file read-size /lfs1/credentials/key.der
```

Known-good current credential sizes are `380` bytes for `crt.der` and `138`
bytes for `key.der`.

## 11) Known-good XIAO build on this machine (May 2026)

This section records the **exact setup and command** that produced a successful
`ble_gatt` firmware build for `xiao_nrf54l15`, including the battery-uplink
branch (`feature/xiao-battery-uplink`).

Use this when `C:/ncs_pouch_soil` does not exist or when builds fail due to mixed
workspaces, missing board definitions, or stale `ncs/pouch` copies.

### Paths on this PC

| Role | Path |
|------|------|
| West workspace root | `C:\Users\Brian\ncs` |
| Pouch source (dev repo) | `C:\Users\Brian\pouch_xiao_nrf54l15` |
| XIAO board files (when not in workspace Zephyr) | `C:\Users\Brian\zephyr` |
| NCS Zephyr SDK (auto-detected) | `C:\ncs\toolchains\0b393f9e1b\opt\zephyr-sdk` |
| Build output | `C:\Users\Brian\pouch_xiao_nrf54l15\examples\ble_gatt\build\` |

West topdir resolves to `C:/Users/Brian/ncs` (manifest: `bluetooth-gateway`).

### Why earlier attempts failed

1. **Mixed pouch trees** — Building from `pouch_xiao_nrf54l15` while west still
   used an old `C:\Users\Brian\ncs\pouch` checkout caused missing Kconfig symbols
   (for example `POUCH_UPLINK_PROCESSING_STACK_SIZE`) and wrong source files.

2. **Wrong workspace age** — `C:\Users\Brian\ncs` was on NCS `v3.0.1`, which does
   not ship `xiao_nrf54l15` in its Zephyr board list. The runbook’s `v3.2.3` stack
   is required for a clean in-tree XIAO board; until `west update` completes to
   `v3.2.3`, pass **`BOARD_ROOT`** pointing at a Zephyr tree that has the XIAO board.

3. **Do not set `ZEPHYR_EXTRA_MODULES`** to the dev repo while west also loads
   `ncs/pouch` — that duplicates the pouch module and breaks Kconfig.

4. **Link error on `mbedtls_x509_crt_info`** — Nordic’s mbedTLS build can define
   `MBEDTLS_X509_REMOVE_INFO`, which strips those helpers. The fix in
   `src/cert.c` (and `src/gateway/cert.c`) guards cert debug logging when that
   symbol is set.

5. **`west update` to v3.2.3** may fail here with Git SSL errors
   (`unable to get local issuer certificate`). The build below works without a
   full workspace refresh as long as **`BOARD_ROOT`** and the NCS-managed SDK are
   set correctly.

6. **Use app-only builds** — `--no-sysbuild` avoids the MCUboot
   `FLASH_DEVICE_ID could not be determined` failure (see section 10).

### Exact build command (verified success)

Run from the **west workspace root**, not from inside `examples/ble_gatt`:

```powershell
$env:ZEPHYR_SDK_INSTALL_DIR = "C:\ncs\toolchains\0b393f9e1b\opt\zephyr-sdk"
cd C:\Users\Brian\ncs
west build -b xiao_nrf54l15/nrf54l15/cpuapp `
  -d C:/Users/Brian/pouch_xiao_nrf54l15/examples/ble_gatt/build `
  -p always --no-sysbuild `
  C:/Users/Brian/pouch_xiao_nrf54l15/examples/ble_gatt `
  -- "-DBOARD_ROOT=C:/Users/Brian/zephyr"
```

Notes on the flags:

- **`-d .../build`** — Puts artifacts under the dev repo’s `examples/ble_gatt/build`
  (not under `ncs/pouch`), so paths stay stable across branches.
- **`-p always`** — Pristine configure; avoids stale `app_version.h` and devicetree.
- **`--no-sysbuild`** — App-only image; required for reliable XIAO flash today.
- **Source dir** — Full path to `examples/ble_gatt` in `pouch_xiao_nrf54l15`.
- **`-DBOARD_ROOT=...`** — Supplies `boards/seeed/xiao_nrf54l15` when the workspace
  Zephyr revision does not include that board yet.

### When `west update` to NCS v3.2.3 succeeds

After a full `west update` from a manifest with `nrf: revision: v3.2.3`
([`west-ncs.yml`](../west-ncs.yml)), you may be able to drop **`BOARD_ROOT`**
and build from inside the pouch tree:

```powershell
$env:ZEPHYR_SDK_INSTALL_DIR = "C:/ncs/toolchains/66cdf9b75e/opt/zephyr-sdk"
cd C:\Users\Brian\pouch_xiao_nrf54l15\examples\ble_gatt
west build -b xiao_nrf54l15/nrf54l15/cpuapp -p always --no-sysbuild
```

Confirm the board is present first:

```powershell
west boards | Select-String xiao_nrf54l15
```

Until then, prefer the **exact command in section 11** with `-DBOARD_ROOT`.
